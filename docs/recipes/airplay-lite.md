# AirPlay 2 на Станции Лайт: установка, кнопки и индикация

Готовая установка **Shairport Sync 5.6.2 + NQPTP 1.2.9**. Колонка появляется в AirPlay
как **Yandex Station Lite**, воспроизводит музыку с iPhone/Mac и принимает команды
с физических кнопок. Каждое нажатие сопровождается короткой вспышкой кольца и тихим сигналом.

!!! info "Проверено 26 октября 2026 на Станции Лайт"
    Модель `yandex,station-micro`, ядро `4.9.68`, Buildroot `2020.02.1`,
    сборка `4778262442`, контроллер кнопок **CY8CMBR3108** на `/dev/input/event1`.
    Владелец подтвердил воспроизведение, громкость, паузу/продолжение, свет и звук кнопок.
    Другие модели и ревизии кнопок требуют адаптации. На них установщик останавливается.

Это самостоятельный пакет. [Старый фикс для Мини 3](airplay.md) рассчитан на другую
сборку с `airplayd`; к этому пакету его применять не нужно.

## 1. Подготовка

На компьютере нужны `adb`, Bash и Python **3.9+**. Docker нужен только для самостоятельной
сборки. На колонке — [root по ADB](../start/root.md), работающий Wi-Fi и около **32 МБ**
свободного места в `/data`. Архив занимает примерно **10,4 МиБ**, распакованные файлы — **26 МиБ**.

Скачать или клонировать репозиторий целиком. Нужны каталог
[`contrib/airplay-lite`](https://github.com/Marker284/yandex-station-extended/tree/main/contrib/airplay-lite)
и два файла рядом с ним:

- [`airplay-lite-5.6.2.tar.gz`](https://github.com/Marker284/yandex-station-extended/raw/main/contrib/packages/airplay-lite-5.6.2.tar.gz);
- [`airplay-lite-5.6.2.tar.gz.sha256`](https://github.com/Marker284/yandex-station-extended/raw/main/contrib/packages/airplay-lite-5.6.2.tar.gz.sha256).

Команды ниже выполняются из корня репозитория. Адрес `192.168.1.50:5555` — пример:
подставить адрес своей Станции. Устройство указывается явно, поэтому другие подключённые
к ADB телефоны не затрагиваются.

```sh
adb devices -l
./contrib/airplay-lite/install.sh --check 192.168.1.50:5555
```

`--check` читает модель, версию ядра, контроллер кнопок, наличие утилит и свободное место.
Если AirPlay уже установлен, показывает его состояние. Файлы на колонке не меняет.

## 2. Узнать настоящее mDNS-имя

У Алисы уже есть собственное объявление Bonjour. Avahi нужно дать **то же имя хоста**,
иначе возможен конфликт адресов и исчезновение устройства из AirPlay.
Обычное `/etc/hostname` (`yandex-station-lite`) для этого не подходит.

На Mac:

```sh
dns-sd -B _yandexio._tcp local.
```

Скопировать имя своей службы `YandexIOReceiver-…`, остановить поиск через `Ctrl+C` и выполнить:

```sh
dns-sd -L 'YandexIOReceiver-EXAMPLE123' _yandexio._tcp local.
```

В ответе будет `can be reached at yandexmicro-EXAMPLE123.local.`. Нужна часть
**`yandexmicro-EXAMPLE123`**, без `.local.`. В обеих командах `EXAMPLE123` заменяется
данными своей колонки. На Linux имя можно посмотреть через `avahi-browse -rt _yandexio._tcp`.

Серийный номер входит в это имя; в общедоступные отчёты его не включают.
Подробнее о конфликте — [«Свой mDNS рядом с maind»](../internals/gotchas.md#avahi).

## 3. Установить пакет

```sh
./contrib/airplay-lite/install.sh 192.168.1.50:5555 yandexmicro-EXAMPLE123
```

Установщик:

1. Проверяет SHA256 архива и каждого файла, подставляет имя mDNS.
2. Проверяет root, модель, ядро, кнопки и свободное место.
3. Загружает пакет во временный каталог `/data`, повторно проверяет файлы.
4. Размещает пакет в `/data/shairport`.
5. При необходимости создаёт пользователя/группу `avahi` без входа в систему.
   Для новой учётной записи нужен свободный UID/GID 86; существующая полная запись используется.
6. Сохраняет исходные `/etc/passwd` и `/etc/group` в `/data/shairport/backup`.
7. Устанавливает `/etc/init.d/S99zairplay`, синхронизирует изменения и возвращает
   корневую файловую систему в исходный режим монтирования.
8. Запускает службы и выводит `AIRPLAY_INSTALL_OK`.

Существующие `/data/shairport` и `S99zairplay` **не перезаписываются**.
Если запуск не удался, файлы остаются для диагностики, а установщик сообщает об ошибке.
Системный `/etc/asound.conf` и штатные скрипты Quasar не изменяются.

Пакет был установлен и проверен на живой колонке по шагам этого рецепта.
Сохранённый автоматический установщик проверяется отдельно: синтаксис, распаковка,
контрольные суммы и `--check`. Повторная чистая установка и перезагрузка для проверки
автозапуска в этой сессии не выполнялись.

## 4. Использование и проверка

На iPhone/Mac в той же сети выбрать **Yandex Station Lite** в AirPlay и включить музыку.

| Действие | Результат |
|---|---|
| `+` / `−` на колонке | Меняется ALSA Master, шаг 5 процентных пунктов |
| Кнопка воспроизведения | Источнику отправляется MPRIS `PlayPause` |
| Принятое нажатие | Вспышка кольца около 140 мс и тихий тон 70 мс |
| Пауза | После выхода из активного состояния запускается Алиса |
| Источник остаётся подключённым | Кнопки продолжают управлять AirPlay, включая продолжение после паузы |
| Источник отключён | Обработчик отпускает кнопки штатному ПО |

Пауза/продолжение зависят от реакции источника и буферизации AirPlay, поэтому могут
срабатывать с задержкой. Отдельная световая индикация показывает приём нажатия сразу.
На ползунке телефона отображается громкость AirPlay; физические кнопки меняют отдельный
ALSA Master. Очень тихий Master ограничивает итоговую громкость и сигнала, и музыки.

Во время воспроизведения **Алиса остановлена**. Таймер выхода из активного состояния —
2 секунды; затем требуется время на запуск её процессов. `/dev/input/event0`
(переключатель микрофона) обработчик AirPlay не перехватывает.

Состояние служб и целостность файлов:

```sh
adb -s 192.168.1.50:5555 shell /data/shairport/airplay.sh status
adb -s 192.168.1.50:5555 shell 'cd /data/shairport && sha256sum -c MANIFEST.sha256'
dns-sd -B _airplay._tcp local.
```

Должны работать `dbus-daemon`, `avahi-daemon`, `nqptp`, `shairport-sync`,
`airplay-buttons` и `monitor`. Установленный автозапуск ждёт `/data` и `/dev/snd/pcmC0D0p`
до 60 секунд. После перезагрузки состояние проверяется той же командой.

## Управление, настройки и резервная копия

```sh
adb -s 192.168.1.50:5555 shell /data/shairport/airplay.sh stop
adb -s 192.168.1.50:5555 shell /data/shairport/airplay.sh start
adb -s 192.168.1.50:5555 shell /data/shairport/airplay.sh restart
```

`stop` останавливает службы AirPlay и возвращает Алису, если она была остановлена этим пакетом.
Чтобы отключить запуск после включения питания, сохранив файлы:

```sh
adb -s 192.168.1.50:5555 shell /data/shairport/airplay.sh stop
adb -s 192.168.1.50:5555 shell 'mount -o remount,rw / && chmod -x /etc/init.d/S99zairplay && sync && mount -o remount,ro /'
```

Для обратного включения заменить `chmod -x` на `chmod +x` и выполнить `airplay.sh start`.

| Путь на колонке | Что хранится |
|---|---|
| `/data/shairport/ap2/shairport.conf` | Имя AirPlay, порт 7000, параметры приёмника и хуки |
| `/data/shairport/etc/avahi-daemon.conf` | Настоящее mDNS-имя этой колонки |
| `/data/shairport/etc/asound.conf` | Отдельный микшер для музыки и сигнала кнопок |
| `/data/shairport/etc/airplay-bus.conf` | Отдельная D-Bus-шина, доступная root |
| `/data/shairport/airplay-buttons.c` | Исходник обработчика кнопок, подсветки и сигнала |
| `/data/shairport/backup/` | Резервные копии системных файлов установщика |
| `/tmp/shairport/` | Логи и PID; хранятся в RAM и исчезают после перезагрузки |

Перед заменой или удалением пакета сохранить его вместе с автозапуском:

```sh
mkdir -p airplay-backup
adb -s 192.168.1.50:5555 pull /data/shairport airplay-backup/
adb -s 192.168.1.50:5555 pull /etc/init.d/S99zairplay airplay-backup/
```

Такая копия содержит настоящее имя устройства, а `backup/passwd.before-airplay` — сведения
о локальных пользователях. Для обмена используется переносимый архив из репозитория.

В рабочей копии, где готовился этот рецепт, дополнительно сохранён локальный снимок
в `.local/airplay-lite/2026-10-26/`: `station-snapshot.tar.gz`, его SHA256 и `station.env`
с адресом ADB и именем mDNS. `.local/` исключён из Git.

## Сборка из сохранённых исходников

```sh
./contrib/airplay-lite/build.sh
```

Скрипт извлекает ARM64-бинарники и зависимости из официального образа
[`mikebrady/shairport-sync:5.6.2`](https://github.com/mikebrady/shairport-sync/tree/5.6.2/docker)
с закреплённым digest:

```text
sha256:b6192daba080e2511716490fa104a0bf96ebbb6dbf49d42a39243d9d6c5f97f9
```

Приёмник собран с AirPlay 2, ALSA и MPRIS; версия интерфейса общей памяти у него и
NQPTP совпадает: **smi11**. Системные библиотеки колонки 32-битные, поэтому запускаются
свои ARM64-библиотеки через `ld-musl-aarch64.so.1 --library-path …`.

Обработчик кнопок собирается в ARM64 Alpine 3.23.4 с GCC 15.2.0, musl и заголовками ALSA.
Digest базового образа и версии пакетов компилятора закреплены в `build.sh`.
Для сборки нужен доступ к Docker Hub и репозиториям Alpine. Если закреплённые пакеты
позже исчезнут с зеркала, готовый архив остаётся пригодным для установки без Docker.

`bundle.py` генерирует WAV сигнала, файловый манифест и архив. В нём нет настроек аккаунта,
ключей, Wi-Fi или серийного номера: вместо имени mDNS находится `@MDNS_HOST@`.
При установке подставляется имя конкретной колонки и пересчитывается манифест.

## Почему устроено именно так

| Проблема, обнаруженная при настройке | Решение в сохранённом пакете |
|---|---|
| Старый фикс сообщает, что `/data/shairport` отсутствует | Установить самостоятельный пакет; исходная сборка с `airplayd` для него не нужна |
| Службы завершаются после выхода из ADB | Запускать через `setsid`; одного `nohup` оказалось недостаточно |
| Avahi не находит пользователя даже с `--no-drop-root` | Создать служебного пользователя/группу `avahi` |
| Системная D-Bus-шина не подходит | Отдельная шина `/tmp/shairport/bus` |
| `Invalid CTL hw:0`, `output_device_error_2` | В отдельном ALSA-конфиге обязательно описание `ctl.hw` |
| `Unknown timer hw:CLASS=3,…` при смешивании сигнала | В том же конфиге обязательно описание `timer.hw` |
| Приёмник и Алиса занимают одну звуковую карту | Хуки активного состояния останавливают Quasar и возвращают его после окончания |
| Алиса наследует настройки AirPlay | Перед запуском очищаются `ALSA_CONFIG_PATH` и `DBUS_SYSTEM_BUS_ADDRESS` |
| После остановки Алисы не работают кнопки | Отдельный ARM64-обработчик `/dev/input/event1` |
| После паузы кнопка запускает Яндекс.Музыку | `EVIOCGRAB` сохраняется до отключения AirPlay-сессии по TCP 7000 |
| Пауза отправляется, но не доходит | Вызов MPRIS через `dbus-send --print-reply` |
| Нужен сигнал одновременно с музыкой | Отдельный 64-битный `dmix`, общий для приёмника и обработчика кнопок |

Кнопки этой ревизии: `114` — тише, `115` — громче, `582` — воспроизведение/пауза.
Подсветка — девять файлов `micro:{red,green,blue}:ring{1,2,3}/brightness`.
Обработчик сохраняет предыдущие значения, кратко включает белую вспышку и возвращает их.

## Диагностика

```sh
adb -s 192.168.1.50:5555 shell 'tail -n 50 /tmp/shairport/shairport-sync.log'
adb -s 192.168.1.50:5555 shell 'tail -n 30 /tmp/shairport/airplay-buttons.log'
adb -s 192.168.1.50:5555 shell 'tail -n 30 /tmp/shairport/avahi-daemon.log'
adb -s 192.168.1.50:5555 shell 'cat /proc/asound/card0/pcm0p/sub0/hw_params'
adb -s 192.168.1.50:5555 shell 'amixer sget Master'
```

В журнале кнопок во время AirPlay должны появляться `ownership: active`, `volume up/down`
и `play/pause`. После отключения источника — `ownership: released`.
Состояние ALSA `closed` в простое нормально. При воспроизведении ожидаются 48 кГц,
два канала и `S16_LE`; сам звук Лайта сводится в моно.

Короткий тест светового и звукового отклика:

```sh
adb -s 192.168.1.50:5555 shell '/data/shairport/run.sh airplay-buttons --feedback; echo TEST_EXIT:$?'
```

Тест выбирает микшер текущего режима: во время AirPlay — отдельный `dmix`, при работающей
Алисе — штатный `aplay`. Успешный результат — `TEST_EXIT:0`.
